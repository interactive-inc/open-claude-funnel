# 再送先と停止意図を維持する

チャネルの配送と、外部ソースの接続・復旧は別の責務として扱う。今回の修正は Funnel の配送、再送ログ、購読、リスナー管理に閉じ、並行して改善されている Flume の公開 API と依存バージョンは変更しない。

## 配送と再送

存在しないチャネルへの送信は、イベントの採番・保存・配送より前に拒否する。再送ログは診断用の要約ではないため、本文を切り詰めない。コネクタの照合は永続 ID を優先し、接続済みの購読情報は送信時に最新設定へ更新する。

exclusive のイベントにはチャネルごとの配送先 ID を記録する。接続者がいなかったイベントは未割り当てとして保存し、再送時に最初の適格なワーカーへ割り当てる。SQLite の割り当ては複合主キーにより競合を排除し、再起動後も同じ所有者を返す。ログの削除・保持期間に合わせて割り当ても削除する。

独自のイベントログは claimExclusive を実装すると未割り当てイベントを再送できる。既存の実装は継承した既定処理でこの割り当てを拒否し、重複配送を避ける。配送先が既に記録されているイベントの再送は引き続き利用できる。

MCP は一つのプロセス内で同じ購読 ID を維持する。最初の通知に失敗したときは、そのイベントの直前から再送する。購読 ID のない独自クライアントは exclusive のライブ配送のみを利用できる。新しいプロセスへ仕事を引き継ぐ場合は同じ ID と受信 offset の保持を呼び出し側が担う。

旧ログから、誰に配送済みだったかは復元できない。このため配送先情報のない履歴を exclusive のワーカーへ再配布しない。過去に短縮して保存した本文も復元できない。この配送契約は外部副作用の exactly-once 実行を保証しない。

## 起動と停止

明示停止は「設定済みだが未起動」と区別して保持し、明示的な start / restart で解除する。停止中の起動は登録を取り消し、起動処理の完了と後始末を待つ。タイムアウト後に外部接続が遅れて完了した場合も停止し、キャンセル済みの notify は拒否する。

復旧の待機中に停止や別の操作が入った場合は、世代と操作番号を照合して古い再試行を取り消す。全停止が完了した後に、古い startAll が監視タイマーを再開することも防ぐ。
