# 接続ライブラリとしての境界

Funnel のジョブは外部の接続を共有し、Agent SDK・Claude Code Channels などの購読者へイベントを届け、返信を外部へ返すこと。エージェントを起動するアプリケーションはホストが作る。SDK・MCP を包まず、ホストが使う入力列と通知値を提供する。[組み込み契約](embedding.md)を参照する。

## 所有者

| 対象 | 所有者 |
| --- | --- |
| Socket Mode / Gateway / poll、再接続 | Flume |
| 接続定義、配信先、fanout / exclusive、offset と再送 | Funnel |
| Agent SDK の query / session、MCP Server / transport / tools | ホスト。`/claude` の入力・通知をそのまま組み込む |
| 実行ディレクトリ、プロセス、設定の保存、資格情報 | ホスト |
| HTTP の待受・認証・公開範囲 | ホスト。Bun 用の薄い server helper は選択可能 |
| 再起動をまたぐイベント・発火状態の保存 | ホストが注入した store |

`new Funnel()` はメモリ内の設定を作る。ファイルを読まず、フォルダを作らず、ポートを開かない。コネクタと待受ポートと認証は明示する。SQLite は任意の sub-entry に隔離する。

既定のメモリ設定 store は、通常のオブジェクト・配列・null prototype の辞書からなる設定データを循環参照も含めて切り離す。初期値・読込結果・書込値・更新の draft や戻り値から保存内容を書き換えられない。更新は同期 callback の正常終了後に共通 schema を検証してから確定し、失敗した draft は捨てる。更新中の別の書込と非同期 callback は拒否し、読込は直前の確定済み設定を返す。関数やクラスインスタンスなど通常の設定データではない値は、ホスト所有の参照として維持する。その内部状態は store の transaction 対象に含めない。

Funnel の生成時に options の値を取得し、registry・チャネル操作・後から作る gateway に同じ時計・logger・停止 signal 等の参照を渡す。元の options オブジェクトを後から差し替えても、生成済み Funnel の依存先を変更しない。注入した時計を進めるなど、依存オブジェクト自身の操作は引き続き反映する。

## 構造

`lib/funnel.ts` が設定ストアとコネクタ registry を組み立てる。engine は接続・チャネルの規則を、gateway は購読・配信・HTTP/WebSocket 境界を持つ。CLI・Claude 起動・設定ファイル同期・ファイル IO の既定実装は持たない。

具体コネクタは `connectors/<type>` から必要なものだけ渡す。カスタムの Flume sources を合流する場合は `/channel` の manifest を使い、source 固有の状態保存は source に渡す。

## 不変条件

- スケジュールの予定 ID は同じ connector 内で一意にし、作成・復元・直接 listener 構築で重複を拒否する。checkpoint の共有で別の予定を実行済みにしない。`entries` の省略は空配列になるが、不正な型を空配列へ置き換えて保存しない。
- スケジュールの診断ログは配送の成否を変えない。診断・onFired のエラー報告の同期例外や Promise 拒否を捕捉し、後続予定・成功済み checkpoint・元の通知エラーを失わない。診断保存の失敗は logger へ通知し、その logger の失敗も処理へ戻さない。通知と発火状態の保存は引き続き必須の成功境界とする。
- スケジュールの start は同時に一つだけ有効にする。停止・再起動後に古い実行から後続予定や timer を再開しない。通知・onFired の待機中に再起動した場合は、その処理の確定後に新しい実行の初回 tick を進める。再起動の start は待機登録までで戻り、通知内から呼んでも待ち合わせで停止しない。成功済み通知の checkpoint は停止後も保存する。host signal と起動用 signal のどちらの取消でも実行を止める。
- スケジュールの時計は発火判定・状態読み取り・次の timer の計算前に検証する。Invalid Date で未来の予定を発火したり、不正な checkpoint を保存したりしない。timer を計算できない場合は接続を非稼働にし、エラーを通知する。時計を直した後の明示的な再起動は可能とする。
- 発火 checkpoint は host store の読み書きで Map と Date を切り離し、不正な時刻を `schedule checkpoint must be a valid timestamp` で拒否する。検証前に状態を削除したり通知したりしない。保存に失敗した場合はホストが保持する以前の Map を変更せず、未保存の発火は再試行対象に残す。
- 配信前に offset と再送先を同期的に記録する。保存失敗を隠してライブ配送を続けない。保存フックが返す `Error` は例外として伝え、`Promise` / thenable は同期保存の契約違反として配信前に拒否する。遅延した拒否も監視して host のエラー通知へ渡す。
- 同期的な保存・配送処理から公開へ再入させない。再入は次の offset の採番前に拒否し、保存順・ライブ入力・再送順を逆転させない。時計と配信データの準備は保存前に済ませる。`onEvent` は配送完了後に呼び、そこからの派生入力の公開は可能とする。
- 監視 callback とエラー通知先からの派生公開は、保存・ライブ配送後に監視通知のキューへ積む。現在のイベントの監視通知を終えてから後続の offset を通知し、再帰呼出による順序逆転を防ぐ。非同期 callback の完了は待たない。gateway の終了時は監視 callback と未通知分を即座に解放し、終了後の監視登録を拒否する。
- HTTP の公開・呼び出しは受信本文の reader を所有し、gateway の終了やリクエスト取消で読み取りをキャンセルして解放する。本文が未完了でも終了要求を待たせず、終了後に外部通信・保存へ進めない。
- 公開・コネクタ呼び出しの HTTP JSON は、解析前に文字列の escape を考慮して深さ128段までに制限する。超過は400で拒否し、再帰的な schema 評価や外部通信・保存へ進めない。
- HTTP の JSON 本文と公開メタデータは、`__proto__` を含む全ての own キーを検証して保持する。特殊キーの削除で本文を変更したり、その配下の不正値を検証から外したりしない。特殊キーの取り込みで prototype を上書きしない。
- WebSocket の Upgrade 値は大文字・小文字を区別せず判定し、有効な表記を通常ルートへ落とさない。認証・停止・購読入力の検査は同じ順序で適用する。
- 購読 URL の生成でも subscriber ID・明示した since を一度取得する。since は0以上の安全な整数だけを受け付け、getter の再読込で別の購読者・再送位置を埋め込まない。既存の base query と特殊文字のエンコードは維持する。
- SQLite の巨大な raw payload は縮小後の JSON も256 KiB以内に制限する。保持候補の識別情報が大きい場合はその項目を省き、元のバイト数と収まる項目を保持する。深すぎる JSON は解析前に識別情報の抽出を省き、診断処理で parser の stack を使い切らない。
- 診断の outcome 前方一致は大文字・小文字を区別し、NUL・`%`・`_`・backslash を通常の文字として比較する。SQLite とメモリで件数制限の前に同じ条件を適用し、対象外の行で必要な診断を押し出さない。条件がサロゲートペアの途中で終わる場合も JavaScript の startsWith と同じ前方一致にする。
- SQLite 診断の raw・processed・connection は別ファイルに保存する。Bun が除去するファイル名の前後の空白は検査前にそろえ、DB の作成・sidecar の予約・権限設定にも同じ名前を使う。相対パス・symbolic link・hard link で同じ保存先を指す設定は初期化前に拒否し、作成・migration による混在を防ぐ。symbolic link の後の `..` は実際の参照先から解決し、文字列だけで親ディレクトリを決めない。DB 本体と別の保存先の `-wal`・`-shm`・`-journal` の重複も拒否し、SQLite の管理ファイルで既存履歴を上書きさせない。新規ファイルの作成後にも実体を再検査し、大文字・小文字や Unicode 表記を区別しないファイルシステムでも同じDBを複数の保存先として使わない。独立した `:memory:` は共有ファイルとみなさない。
- SQLite の保存先は前後の空白を除いた空でない OS のファイルパスか `:memory:` とする。空パス・NUL・SQLite URI はディレクトリや DB の作成前に拒否し、NUL による名前の切り詰めや URI の別名・接続設定でファイル検査とロック方針を回避させない。
- SQLite 再送ログは構築時に保存先と保持設定を一度取得し、イベントと exclusive 割当で同じ保存先を使う。getter の再読込で割当を別ファイルへ保存し、再起動後に二重割当させない。保持の適用と割当の掃除も同じ設定値で判断する。
- SQLite の文字列引数は JSON の escape を通して DB 内で復元し、不完全なサロゲートを別の文字列へ変換しない。本文の JSON と索引に同じ値を保存し、検索条件にも同じ変換を使う。exclusive 割当の所有者比較も DB 内で行い、読み戻しによるワーカー ID の欠落やチャネル ID の衝突を防ぐ。
- SQLite 保存処理の seq・時刻・イベントも一度取得し、検証・保存・採番最大値・返却行に同じ値を使う。検証後の getter 再読込で負の seq を保存したり、保存した時刻と返却する時刻を違わせない。
- SQLite の失敗値も安全に Error へ変換する。印字できない例外でロールバック後の失敗結果や保守通知を壊さず、commit 後の VACUUM・割当掃除の失敗を保存失敗へ変えない。
- SQLite 保存部品の保守通知も共通の callback 監視を通す。独自の then・catch を持つ Promise の拒否を漏らさず、完了済みの clear・採番と後続保存を維持する。
- SQLite 診断ログとメモリ再送ログの保持上限も一度取得して検証・適用する。getter の再読込で設定済みの件数・期限・バイト上限を失わず、0 の保持上限も維持する。
- SQLite 診断の保存・圧縮失敗を通知する logger も共通の callback 監視を通す。独自の then・catch を持つ Promise の拒否を処理へ漏らさず、各テーブルの元の失敗を通知する。
- 診断検索の明示的な件数・採番は非負の安全な整数に制限し、空のテーブルでも不正な値を拒否する。メモリでも不正な指定を全件取得や空の結果へ変えない。
- 診断検索は同期で完了する。`/debug` は Promise・thenable を履歴として JSON 化せず、500の契約エラーを返す。元の非同期拒否は検索名とチャネル ID を付けて host の onError へ通知し、ストア修復後の検索は再開できる。
- SQLite 検索とチャネル別再送も、scope・種別・採番・件数・表固有フィルタを一度取得して使う。診断の共通検索条件はメモリと同じコピー・検証を通し、getter の再読込で絞り込みを外したり0件の指定を失ったりしない。
- SQLite 診断検索は、返す本文のチャネル・コネクタ・種別が指定した検索範囲と一致することを確認する。検索用の列と本文の不整合で別の範囲の記録を返さず、`diagnostic routing index conflicts with stored identity` で拒否する。
- イベント ID・処理結果の完全一致と前方一致・接続状態の単一指定と集合指定も本文に対して確認する。検索用の列だけが条件を満たす記録を正常な検索結果として返さず、`diagnostic filter index conflicts with stored event` で拒否する。
- SQLite の利用者定義インデックス列は、定義・書込・完全一致・prefix・集合検索で識別子として引用する。許可された小文字の名前が SQL の予約語でも利用できる。重複列は DB を開く前に拒否し、不正な定義で既存の表を部分変更しない。
- SQLite 保存部品自身も path・保持上限を一度取得する。ディレクトリ作成と DB 接続で同じ path を使い、他の DB を開かない。最初の保持値を検証して適用し、0の上限や不正値の拒否を getter の再読込で変えない。
- 診断ログの検索結果は保存行から切り離す。返却した本文・所属 ID・状態・採番の加工で、保存済みの事実や後続検索の絞り込みを変えさせない。
- メモリ診断ログも記録・検索の定義済み項目を明示的に取得する。prototype の getter で渡された必須値・所属条件・件数上限・表固有フィルタを落とさず、型に適合したクラス入力でも範囲外の行を返さない。
- メモリ診断ログは入力と時計の取得後に採番する。時計内から同じ表へ記録しても seq を重複させず、失敗した外側の記録は行も採番も残さない。
- メモリ診断ログの保存時刻も有効なミリ秒 timestamp に制限する。NaN・Infinity・Date の範囲外は保存・採番前に拒否し、有効な0・負数・小数は保持する。
- 診断ログの clear は表ごとの採番最大値を保持する。メモリでも消去前の seq を新しい行へ再利用し、古い参照を別の診断へ向けない。
- 各送信の直前に、選択時と同じ購読登録が有効であることを確認する。保存処理・先行送信・エラー通知から解除された接続や、同じ socket の新しい登録へ古い登録のイベントを送らない。socket の状態取得・送信準備でも取消と登録の差し替えを再確認し、古い送信の失敗で新しい登録を削除・切断しない。確定済みの exclusive 割当は別ワーカーへ付け替えない。
- 配信値は発行元・購読者の可変オブジェクトから切り離し、別の購読や再送履歴を書き換えられない snapshot にする。
- 購読登録・明示的なチャネル更新・直接の再送では、チャネルとワーカーの指定とコネクタフィルタ配列をホストの入力から切り離す。再送位置は一度取得した同じ値を検証と読込に使う。診断で返す購読情報から内部フィルタを変更させない。明示的なチャネル更新は進行中の同一プロセス再送にも反映する。
- fanout と exclusive の配送先、明示停止、停止途中のキャンセルを保持する。
- 再起動が接続終了を待っている間も、後から来た停止・全体停止・再起動の要求を優先する。古い再起動要求は接続を開き直さず、取消結果を返す。全体停止が完了した後の新たな明示的再起動は可能とする。
- 接続の実行状態・起動ロック・再試行・停止意図は `(channelId, connectorId)` の組で識別する。名前は変更可能なラベルであり、区切り文字を連結したキーにはしない。
- 設定から外れた接続を保持済みの名前で操作するとき、同名の候補が複数あれば選ばず拒否する。`stopAll` / `close` は名前を解決せず全接続を停止できる。現在の設定が一意に指す接続と、候補が一つだけの接続は個別に操作できる。
- 起動中の接続も受付時の名前で保持し、設定削除後の個別停止を起動信号へ伝える。起動完了直前に起動中・実行中の両方へ登録されていても、同じ ID の組は一候補として扱う。
- 復旧処理中・復旧待ち・再試行待ちの接続も名前解決の候補に含め、接続を閉じてから待機へ移る間も同じ ID を保持する。設定が一時的に外れている間の停止でも、その ID の待機を取り消して停止意図を保持し、設定の復元で古い待機から再開させない。
- 配送時はその ID の現在の設定を参照する。削除した接続の入力を同名の新しい接続として届けない。監視処理は削除した接続を閉じ、失敗・停止の状態も対応する ID がなくなった時点で解放する。
- チャネル ID は空でなく設定全体で一意、接続 ID は空でなく所属チャネル内で一意とする。チャネル名は設定全体、接続名は所属チャネル内で重複させない。保存設定とホスト提供 store の読み取りを検証し、不正な識別情報で配送を始めない。追加時の生成 ID の衝突は保存内容を変更する前に拒否する。
- gateway の名前・ID 解決は一度の設定読込で行う。指定値が別々のチャネルの名前と ID に一致する場合は `channel-ambiguous` で拒否し、名前の優先順位で別の配送先を選ばない。HTTP 公開と WebSocket 購読は認証後に HTTP 400 を返す。同一チャネル自身の名前と ID が一致する場合は利用できる。
- HTTP クライアントの接続開始・停止・再起動は、成功 status に加えて JSON の `ok: true` を確認してから成功を返す。空・HTML・不正な型の応答はエラーとし、`ok: false` の理由を保持する。
- HTTP クライアントの一覧取得は、HTTP エラーの読み取らない本文をキャンセルする。後始末の失敗や未完了によって、元の HTTP status の返却を妨げない。
- Gateway 公開クライアントと GitHub・Discord adapter は、HTTP エラー本文の読込失敗でも既知の status を保持する。安全に整形した読込失敗の理由を添え、正常な後続要求を妨げない。adapter の取消は本文読込後にも確認し、HTTP エラーへ置き換えない。
- HTTP クライアントの可用性確認・資格情報取得・通信・本文読込が印字できない値を投げても、固定の理由を持つ error 結果を返す。エラーの整形自体から Promise を拒否させない。
- HTTP クライアントはパスへ入れる空文字・`.`・`..` の名前を資格情報の取得と通信の前に拒否する。URL 正規化で操作先を変えない。スラッシュや percent 記号を含むその他の名前は segment としてエンコードする。
- listener registry の配送 callback は、現在の名前とともに確定済みのチャネル ID・接続 ID を渡す。gateway の内部配送はその ID で現在の設定を確認し、外部入力用の名前・ID 解決を通さない。改名や名前と別 ID の衝突があっても配送元を維持し、コネクタのメタデータで内部の識別情報を上書きさせない。
- listener factory の結果は起動前に取り込み、同じ listener・channel ID・config の基本項目を管理と後始末へ使う。起動中に戻り値を書き換えても別の接続を登録・停止せず、prototype の getter で渡した名前・種別・ID も保持する。
- 環境変数参照からの資格情報は、渡された環境辞書自身が持つ空でない文字列だけを使う。継承プロパティや文字列以外の値を token に変換せず、未設定として外部接続前に拒否する。
- 資格情報の解決に使うリテラル値・参照名は文字列として検証し、使用する値と環境辞書を一度だけ取得する。所有確認と読込で別の辞書やキーを使わず、オブジェクトを環境変数名へ暗黙変換しない。有効なリテラルを優先する既存の規則は維持する。
- Channel の登録時に ID・名前・build 関数を一度取得して保持する。呼び出し元の変更で起動・失敗時の削除・解除の対象をずらさず、build の元の receiver は維持する。getter から停止や同じ ID の登録が起きた場合は、登録確定前に受付と重複を再確認する。
- `defineChannel` も ID・名前・build を明示的に取得し、prototype 上の getter・method を持つクラスを受け付ける。manifest の snapshot を凍結し、factory が使う元のインスタンスや内部状態は凍結しない。
- runtime の transform はイベントごとに一度取得し、元の runtime を receiver として呼ぶ。getter の二重取得でイベントを失わず、印字できない変換エラーも transform の失敗として報告する。
- transform の Promise・thenable も配送前に拒否し、拒否を監視する。非同期結果を本文と誤認して undefined を配送せず、対象イベントの失敗を報告した後も次のイベントを受信する。
- コネクタの operation は同じ表で own property の確認と関数取得を行い、別の表の継承関数を誤実行しない。adapter の factory も一度取得し、元の descriptor を receiver として呼ぶ。
- コネクタの buildConfig・applyUpdate・operation は同期の設定 transaction 内で完了する。Promise・thenable は明示的な契約エラーとして commit 前に拒否し、遅延拒否も監視して未処理拒否にしない。
- createListener・createAdapter・secretTokens も同期の descriptor hook として Promise・thenable を拒否する。生成結果を listener・adapter・token 配列と誤認せず、遅延拒否を監視する。接続ライフサイクルと adapter.call の非同期処理は維持する。
- 同期 hook の thenable 判定では then を一度取得し、同じ関数を使って拒否を監視する。getter の再読込で監視を外さず、別の Promise への解決でも拒否を取りこぼさない。
- 設定ストア更新とイベント保存も同じ同期結果の検査を使う。then の再取得で契約エラーを TypeError に変えたり、元の保存失敗の監視・ホスト通知を失ったりしない。
- 実 Promise は realm に依存しないネイティブ判定と組み込み then で拒否・監視する。then を隠す・getter から例外を投げる Promise も同期の保存・設定結果として通さず、元の拒否を監視する。
- 再送の例外値も安全に正規化する。同一プロセスの購読は全読み取りを拒否して解除し、WebSocket は1011で閉じる。印字できない例外で登録・socket を残したり、host の open callback へ例外を漏らしたりしない。
- 保存先から取得した再送イベントは検査前に切り離し、同じ offset・metadata・排他割当で順序検査・配送先判定・配送を行う。getter の再読込や割当 callback 内からの元データの変更で、検査済みの本文・配送先・offset を差し替えない。コピー中に取消された購読は排他割当前に終了する。
- ライブ配送・監視通知も印字できない例外を安全に正規化する。送信・buffer 取得の失敗はその socket だけを解除して1011で閉じ、他の配信先・監視通知を続ける。監視 callback の失敗も元の通知先へ報告する。
- Channel の解除は呼び出し時の登録だけを対象にする。未登録 ID の解除は何もせず完了し、後から追加した同じ ID の登録を停止・削除しない。
- time channel は生成時に cron・変換関数・状態保存先と catch-up 方針の値を取得する。後から渡した設定や方針を変更しても、再構築時の動作・保存先・追いつき範囲を変えない。状態保存先のオブジェクト自身はホスト所有のまま使う。
- コネクタの共通エラー文字列化は、例外値の message 取得や文字列変換が失敗しても固定の説明を返す。配送失敗の報告自体でイベントの受信処理を終了させない。
- Listener Registry の起動・停止・監視失敗も安全な文字列化を使い、印字できない例外で後始末・失敗結果・onError 通知を飛ばさない。Error インスタンスは維持し、認証失敗の再試行判定を変えない。
- Listener Registry は待機中の起動を実行する前と設定・factory の呼出後にも停止要求を確認する。停止済みの起動から接続を開かず、factory が返した未起動 listener も後始末する。
- Listener Registry の全体停止・破棄は設定ストアの障害でも全接続の後始末を続ける。停止ログの現在名を取得できなければ保持済みの名前を使い、設定読込の失敗を onError へ通知する。一つの接続の停止失敗で他の後始末を飛ばさない。
- Gateway Server は module の停止と host callback の呼出前に停止 Promise を公開する。取消 callback 内からの start も停止済みとして拒否し、再入した stop は同じ後始末の完了を待つ。
- Gateway Server と Module の直接構築でも設定値を一度取得する。公開範囲の検査と HTTP 認証で同じ token を使い、イベントログの選択と所有権判定を一致させる。getter の再読込で認証を無効化したり、ホスト所有のログを閉じたりしない。
- Gateway の直接公開は入力とメタデータを設定解決前に取得し、同じチャネル・コネクタ・本文で解決・保存・配送する。ホストの設定読込中の入力変更を公開内容へ反映せず、入力取得中に停止した場合は公開しない。
- Channel Supervisor の起動中は最初のチャネル群の完了 Promise を共有し、並行・再入した `start` を準備完了前に成功させない。同じチャネルを重複起動せず、起動中の停止でも古い処理から再開しない。
- Channel Supervisor はホストの設定値を構築時に取得し、同じ signal で受付判定・終了・監視解除を行う。終了時は abort ハンドラを外し、すでに取消済みの signal にハンドラを残さない。終了 Promise を後始末より先に公開して並行・再入した停止で共有し、所有する registry も閉じる。
- Channel Supervisor の起動・終了と `Channel.build` に渡す logger も保護する。同期例外・非同期拒否で失敗した登録の削除を妨げず、他のチャネルの起動や同じ ID の再登録を止めない。
- Flume を使う listener の診断書き込みと logger は監視用の出力として保護する。同期例外・非同期拒否で起動・配送・停止を中断しない。診断失敗は接続の文脈付きで logger へ通知し、logger 自身の失敗を再帰的に報告しない。実際の通知エラーと後続イベントの処理を失わない。
- Flume の host log observer も共通の callback 監視を通す。独自の then・catch を持つ Promise の元の拒否を診断に記録し、status の反映や source の後始末を妨げない。
- Discord の自己投稿は、bot フラグに加えて既知の自分の user ID でも除外する。部分的な更新イベントで bot フラグが省略されても、自己投稿を購読者へ戻さない。空の自分 ID と空の投稿者 ID を同一人物として扱わない。新しい READY は前の本人識別を置き換える。ID が欠けた場合は古い識別を再利用せず、次の有効な READY まで配送を止める。空の `user.id` が有効な `user_id` を隠さない。
- Discord の公開イベント processor は JSON 本文を生成できない入力を成功扱いしない。`undefined`・function・symbol・本文を返さない `toJSON` は `Discord event could not be serialized` で拒否し、有効な `null`・false・0・空文字の JSON は保持する。自己投稿の除外は本文のシリアライズ前に行う。
- コネクタの更新は、指定された設定値を検証してから保存する。Slack の `minify`、GitHub の取得間隔、資格情報スロットの不正な型を成功扱いで無視しない。省略された設定は引き継ぎ、検証に失敗した更新は保存済み設定を置き換えない。
- コネクタ追加と Funnel の初期設定でも、指定された資格情報・`minify`・取得間隔を各コネクタの schema で検証する。不正な型を省略とみなして既定値へ置き換えず、失敗した接続設定を追加しない。
- 資格情報の重複検査では更新対象の接続自身だけを除外する。別チャネルで同じ接続 ID を使っていても検査対象から外さず、追加と更新の失敗では以前の設定を維持する。コネクタ固有操作の戻り値にも同じ検査を適用し、元の設定オブジェクトを変更して返す操作でも迂回させない。
- descriptor が返す token 配列は registry がコピーして保持する。次の hook 呼出で同じ配列を再利用しても、検査中の候補の資格情報を上書きせず、重複していない追加・更新・固有操作を誤って拒否しない。
- コネクタ固有操作の config・result は重複検査より先に一度取得し、同じ config を検査・保存する。getter の再読込や result の取得で検査後の資格情報を差し替えず、競合時は元の設定を維持する。
- コネクタ操作は descriptor の operations 自身に登録した関数だけを呼ぶ。未登録名や prototype 由来の名前は通常の未定義操作エラーにし、設定を変更しない。標準オブジェクトと同名でも明示した操作は利用できる。
- 同一プロセスの入力列も WebSocket と同じ配送先選択・再送を使う。全件を観測する onEvent を配送先として代用しない。
- SDK / MCP のインスタンスと設定を複製・所有しない。入力列を止めてもホストの SDK タスク・MCP サーバーには干渉しない。
- SDK 入力列はソースの next・done・value を取得した後にも終了状態を確認する。getter からの取消後に次の読込や変換を始めず、ソースの cleanup を一度だけ実行する。
- `alive` は接続または復旧処理が生きていること、`connected` は実接続を表す。根拠は Flume の現在値で、遅れて届く状態ログは履歴として扱う。
- listener の配送成功後に行う統計時刻の取得失敗は診断として報告し、成功済み通知を失敗へ変えない。配送件数を維持し、配送エラーへ加算せず、最後の有効な時刻を保持する。時計の復旧後は次の通知で時刻更新を再開する。
- 配送直前の設定読込と名前・所属 ID の取得後にも listener の取消を確認する。ホストの読込処理内から個別停止・全体停止・破棄を要求した場合、新たな notify を始めない。再起動後も古い listener の通知を拒否する。
- listener registry の監視間隔・起動 timeout・backoff 上限は0以上2147483647ms以下の有限値に制限する。NaN・Infinity・負値・タイマーの上限超過を1msへ変換して監視や再試行を過密にしない。
- listener の `isAlive` が例外を投げた場合は接続の文脈付きで診断を報告し、その回の判定を見送る。他の接続の復旧・再試行を妨げず、取得不能な状態だけで動作中の接続を再起動しない。診断 callback が停止を要求した場合は残りの監視を中止する。
- `isAlive`・`isConnected` は同期の boolean だけを受け付ける。undefined・null・数値・文字列や Promise・thenable を truthy/falsy で状態へ変換せず、元の非同期拒否も文脈付きで通知する。状態一覧にも不正な値を載せず、評価不能な接続はその回の自動復旧判断から外す。
- 停止・明示起動・設定削除による backoff の取消は、所有する signal の reason または AbortError と照合して通常終了にする。取消後の古い復旧を再開せず、同時に発生した別の待機エラーは障害として報告する。
- 監視内の並列復旧・再試行の失敗は接続単位で報告する。他の処理が終わるまで監視ロックを保持し、一件の失敗で後続の再試行キューを飛ばさない。診断 callback が停止を要求した後は次の処理群へ進めない。
- 自動復旧は listener registry が失敗・欠落した接続だけに適用する。Flume が接続し直している間は介入しない。
- 既定のメモリ再送は件数とバイト数で制限し、保持の削除で offset を巻き戻さない。
- メモリと SQLite の再送位置と明示的な取得件数は、非負の安全な整数に制限する。不正な値を空の履歴や全件取得へ変換しない。取得件数の省略は保持中の全件、0 は空の結果とする。
- メモリログも offset の昇順で再送・保持削除し、保存順序の逆転で新しい履歴を落とさない。保持中の同じ offset の重複や不正な offset は保存前に拒否する。メタデータの取得に失敗した保存では本文・バイト数・最大 offset を変更しない。
- メモリログと broadcaster の再送バッファは exclusive 割当の UTF-8 バイト数も保持上限へ算入する。再送時の claim による割当の増分も反映し、上限超過時は古い保持履歴を削除する。現在の配送結果や採番の最大値は保持削除で取り消さない。
- broadcaster の送信待ちバイト数・再送件数・再送バイト数の上限は、それぞれ一度取得した値を検証・適用する。getter の再読込で0の上限を緩めたり、不正値を後から有効値へ差し替えて受け付けたりしない。
- offset は非負の安全な整数で復元し、発行する offset はその範囲内で単調増加させる。壊れた保存先の最大値を受け入れて初期値へ戻したり、小数・Infinity の位置を配信したりしない。上限に達した後の公開は、保存・配送・採番の変更前に拒否する。
- gateway の時計は有効な日時を表すミリ秒値として検証し、不正な時刻で起動・公開を進めない。稼働時間と最終配送時刻は時刻 0 を未設定と区別する。メモリ時計は構築・設定・取得時に Date をコピーし、ホストの日時の加工で時計を変更させない。
- SQLite も採番の最大値を本文とは別に保存する。本文と採番を同じ transaction で更新し、保持削除・clear・再起動で seq / offset を再利用しない。既存 DB の移行では残っている行の最大値を引き継ぐ。移行前に削除済みだった採番は復元できない。
- 再送本文・メタデータ・exclusive 割当はメモリと SQLite で共通の schema を使って保存前に検証する。SQLite は読込・claim 時にも検証する。構文上は JSON でも形が不正なデータは `replay event data is invalid` とし、空の履歴や未割当として扱わない。失敗した保存では採番を進めず、壊れた履歴を claim しない。辞書の特殊なキーも値を検証して保持する。
- 再送レコードの専用 channel / connector ID を配送先の正本とし、メタデータの不足した ID を補う。両者が矛盾する保存・読込は `replay routing metadata conflicts with stored identity` で拒否する。メモリと SQLite で同じ規則を使い、チャネル指定のある履歴をメタデータ欠落によって全体配送へ広げない。
- 独自ストアの exclusive claim は同期的な boolean のみ受け付ける。返された `Error` や非同期・不正な結果を成功とみなさず、再送と割当のキャッシュ前に拒否する。非同期の拒否は host のエラー通知へ渡す。
- WebSocket は再送開始前に配送先へ登録する。再送中の新着入力は送信待ちバイト上限のある列へ保持し、履歴の後に順序どおり送る。上限超過は1009で切断し、再送失敗・取消・登録の差替えでは古い待機列を破棄する。
- exclusive claim は正の安全な整数の offset と空でないチャネル・ワーカー ID だけを受け付ける。チャネル指定のある履歴を別チャネルから claim させない。不正な要求は割当を変更せず false を返し、全体向け履歴のチャネル別割当は維持する。
- SQLite の件数・期限・バイト上限による行削除は、本文と採番と同じ transaction に含める。保持削除が失敗した入力は保存も配送もしない。commit 後の VACUUM と旧版から残った孤立割当の掃除は保守処理として分け、失敗時も成功済みの保存結果を失敗へ変えない。
- SQLite の再送本文と exclusive 割当は同じ DB 接続を共有する。本文の削除時は対応する割当も同じ transaction で削除し、失敗時は両方を復元する。新規行の挿入時は同じ offset の残存割当を取り除き、期限切れ履歴の後に保存した別の入力へ古い配送先を引き継がせない。重複保存の拒否では既存の割当を維持する。clear 後の保守通知から作られた新しい入力と割当も、後続の掃除で取り消さない。
- SQLite のバイト確認間隔は挿入行数で進め、一括保存でも閾値に達した transaction の末尾で確認する。保持削除に失敗した場合は確認用カウンタもロールバックして再試行で確認を省かない。clear は削除後・保守通知前にカウンタを初期化し、通知先が新たに保存した行の進捗を失わない。
- 同一プロセスの再送はページ単位で読み取りに追従し、履歴件数をライブ入力のキュー上限と混同しない。購読開始時の再送上限と、それ以降のライブ入力を分けて重複を防ぐ。
- 保存先の同期 callback から同じ購読の読み取りへ再入しても、実行中の再送 iterator を呼び直さない。再入した読み取りは先行する読み取りの後に処理し、新着入力への切替・取消・保存先の失敗でも順序と完了を保つ。
- チャネル ID は辞書の継承プロパティとして解釈せず、exclusive 割当の作成・参照とも実際のキーとして扱う。特殊な名前でも未配送の割当を失わず、別チャネルの割当と混同しない。
- 注入した永続ログはホストが閉じる。ホスト所有のサーバーはホストが停止する。Bun helper が所有するサーバーの停止では古い接続も閉じる。
- gateway の停止開始後は HTTP 操作・WebSocket 購読・既存 registry 経由の再起動を受け付けない。本文の読み取り後にも停止を確認し、停止をまたいだ要求から新たな外部送信を始めない。gateway が所有する購読と registry を終了し、ホスト所有の待受と独自のルートは継続できる。
- HTTP 経由のコネクタ呼び出しには gateway 所有の取消 signal と要求元の signal を合成して渡す。チャネル操作は設定取得・adapter 生成の前後で取消を確認し、組み込みadapterは送信直前と応答本文の読込後にも確認する。停止・破棄・全体 abort で進行中の通信を取り消し、取消を見逃したadapterの遅い成功も返さない。直接の呼び出しでも同じ `CallInput.signal` を使える。
- 設定読込や購読オプションの取得中に停止・破棄・全体 abort が始まっても、新たな購読を残さない。WebSocket は設定解決後にも停止を確認して upgrade 前に HTTP 503 を返す。同一プロセスの購読は作成後にも確認し、途中で作った列を解除して停止エラーを返す。
- 同じ gateway の並行した `start()` は一つの起動を待ち、同じ成功・失敗を返す。途中の呼び出しで稼働開始時刻を更新しない。起動中の全体停止は起動を失敗させる。致命的な起動失敗では開いた接続と所有する待受を閉じ、明示的な再試行では新しい起動時刻を使う。
- observer から停止を待っても循環待ちしない。callback の配送と source の停止を混同しない。
- 配信 observer の例外、Promise / thenable の失敗は logger と `onError` へ独立して渡す。エラー通知先の同期例外や非同期失敗で、他の配送やプロセスを止めない。配送中に登録した observer は次回から参加し、解除・再登録で同じイベントを二度呼ばない。
- observer の解除と通知キューは登録単位で識別する。同じ関数を再登録しても、古い unsubscribe で新しい登録を削除せず、以前の登録宛ての通知を新しい登録へ渡さない。登録中の同じ関数への重複 subscribe は一つの登録として維持する。
- host callback とエラー通知先が返す実 Promise は、realm や独自の then・catch に依存せず組み込み then で監視する。元の拒否を通知し、通知先自身の拒否は処理へ戻さない。callback と同期例外の通知は引き続き同期で実行する。
- gateway の起動・購読・切断の通常ログも、接続状態を変更する処理と分ける。logger の失敗は `onError` へ渡し、待受だけが残った起動失敗や WebSocket callback の例外にしない。再送失敗の logger と `onError` は独立して呼び、通知先の失敗をホストの WebSocket callback へ漏らさない。
- 通常ログの失敗値は安全に Error へ正規化してから `onError` へ渡す。文字列化できない値や revoked proxy の同期例外・非同期拒否でも通知を失わず、通常の Error は元のインスタンスを保持する。
- HTTP の connector call も adapter 生成・呼出の失敗値を Error へ正規化してから framework へ渡す。文字列・null・revoked proxy や message を取得できない Error でも500の JSON エラー応答を保ち、停止中の503と既存の HTTPException は維持する。
- 組み込み HTTP ルートは共通の例外境界を通す。イベント保存・診断検索・設定読込・listener 操作の同期例外と非同期拒否を framework の検査前に正規化し、JSON 応答を維持する。保存失敗を公開成功に変えず、既存の HTTPException の status・header・body はそのまま返す。
- listener registry もログと `onError` の同期例外・非同期失敗を接続管理へ戻さない。通常ログの失敗で接続を停止したり、停止結果・再試行可否・自動復旧を変更したりしない。起動の期限後に完了した接続の後始末でも、元の失敗を通知して未処理の Promise 拒否を残さない。
- 起動の期限と復旧待ちにキャンセルを伝え、正常起動や停止後に不要なタイマーを残さない。ホストが独自の sleep を渡す場合も、渡された AbortSignal に従う。
- 組み込みの Slack / Discord / GitHub listener はホストの停止信号と registry の接続所有信号を合成して Flume へ渡す。Slack の事前認証 HTTP と応答本文の読み取りにも同じ信号を伝え、取り消された起動から遅れて接続を開かない。
- Slack は listener 自身の実行スコープも取り消せるようにし、直接の停止を認証・前処理・reaction へ伝える。停止後に新しい配送や補助送信を始めず、旧スコープの遅延完了で再起動済みの接続を変更しない。実行中の同じ listener への重複起動は拒否し、取り消された Flume の起動が遅れて成功しても接続を閉じる。
- GitHub・Discord の直接起動も、接続ハンドルの取得前から取消可能な実行スコープで管理する。stop は起動中の信号も取り消し、重複 start は接続を作る前に拒否する。取り消された起動の遅延失敗で、再起動後の接続を停止しない。

0.72 は起動管理と暗黙のディレクトリを削除する破壊的変更。旧 API の互換 facade を重ねると同じ責任が本体へ戻るため設けない。

## 受信処理が遅い場合

Slack の受信重複はチャネルとイベント時刻の組で識別し、10秒の窓で除外する。窓を過ぎた判定を別イベントの到着有無に依存させない。空の識別情報を同じイベントとみなさず、JSON 化に失敗した処理では重複履歴を確定しない。これは受信の短期重複除外であり、外部副作用の実行完了や一度だけの処理を保証するものではない。

Slack の subtype は省略または許可された文字列だけを受け付け、不正な型を省略として扱わない。自身のメンションは識別子の文字列に完全一致させて本文から除去する。自身の識別子が空の場合は、空のメンションや空の投稿者情報を自身のものとして判定しない。

Slack の重複除外で使用する時計は有効なミリ秒時刻に制限する。不正な時計値では配送と履歴変更の前に失敗させ、時計が復旧した後の再試行と既存の重複履歴を保つ。

Slack の添付を軽量化する際、section block の本文と fields は併用されるため両方を順序どおり残す。入力データは変更せず、添付の既存本文に block の内容を追記する。

添付の rich text と表のセルでは、user・channel・usergroup の参照を Slack のメンション表記へ変換し、参照先の識別子を配送本文に残す。

Flume source の入力は Flume の上限付き pull stream で直列に処理する。既定のバッファはログを含めて 1000 件で、超過時は Flume の drop-oldest と overflow ログに従う。無制限の Promise 待機列は作らない。この段階で未処理の入力は Funnel の再送ログへ記録されていないため、再送の保証範囲には含まれない。

停止は待機中の入力を破棄する。実行中のホスト callback の完了は待たず、callback 自身からも停止できる。状態ログの処理は完了させてから stopped を記録する。配送失敗と source の終了失敗は診断ログとホストの logger へ渡す。

受信 callback が失敗した場合も、後続イベントの配送を継続する。受信・起動・切断のエラーを受ける診断ストアや logger の例外は独立して扱い、片方の障害で他方への通知を省略したり、配送ループを終了したりしない。起動の失敗は元のエラーを呼び出し元へ返し、切断のエラー報告で停止処理を中断しない。logger が返す Promise の拒否も未処理の拒否にしない。

Slack の reaction は配送後の補助処理として進め、その失敗通知も診断ストアと logger へ独立して渡す。通知先の同期例外や Promise の拒否で未処理の拒否を作らず、後続の受信を妨げない。Flume のログ変換と診断 recorder は通知先の戻り値を捨てず、呼び出し元が非同期失敗を観測できるようにする。

Slack adapter は送信本文を一度取得してフォームへ変換する。オブジェクト判定後に getter を読み直さず、prototype と同名の own 項目も通常の JSON フィールドとして保持する。

GitHub・Discord adapter もパスと送信対象の本文を一度取得し、同じ値で URL・JSON 本文を組み立てる。GET・HEAD では不要な本文 getter を呼ばず、存在確認後の再取得で本文を落とさない。

標準 adapter は JSON 化する数値を検査し、`NaN`・無限大を `null` に変えて外部 API へ送らない。プログラム経由の呼び出しでも、本文や配列・オブジェクト内の不正数値は通信前に拒否する。

## 定期実行の再試行と停止

schedule connector は一件の配送が成功するたびに、ホストの発火状態ストアへ進捗を保存してから `onFired` を呼ぶ。後続の配送が失敗しても、保存済みの成功分を再実行しない。配送とストア保存は別の操作なので、配送後に保存が失敗した場合やその間にプロセスが終了した場合の重複は、利用側で `schedule_id` と `fired_at` を用いて防ぐ。

発火状態ストアの load・save は同期で完了する。Promise・thenable を返す実装は契約エラーとして拒否し、元の非同期拒否も診断へ記録する。非同期の読込を空の進捗とみなさず、保存・削除済み項目の掃除・skip・検索範囲の更新が完了する前に成功扱いしない。

進捗データは Map の反復契約を要求する。反復できない辞書・array-like・プリミティブを空の進捗へ変換せず、配送・掃除・以前の進捗の置換より先に拒否する。別 realm の Map は引き続き受け付け、日時をコピーする。

進捗の予定 ID は文字列だけを受け付ける。保存データの不正な ID を削除対象とみなして単発予定を再配送せず、掃除・保存・配送より先に拒否する。既定ストアへの不正な保存も以前の正常な進捗を置き換えない。

既定の発火状態は channel ID と connector ID の組で分離し、ID 内の区切り文字で衝突させない。同じ ID の接続を再作成した場合は状態を引き継ぐ。メモリ状態ストアは保存・読込時に日時もコピーし、`onFired` に渡す予定と日時も内部状態から切り離す。実行用の予定は listener 構築時にコピーする。ホストが渡した設定や callback の引数を加工しても、後続の発火の ID・本文や保存済みの進捗に影響させない。設定変更はホストの設定更新と listener の再作成で反映する。

cron は5フィールドの十進整数・範囲・リスト・step を扱う。空の範囲端点・値のない step・16進数・指数表記は受け付けない。日と曜日のいずれかが `*` から始まる場合は両方の一致が必要で、両方が数値から始まる場合はどちらかの一致で発火する。`*/2` も先頭が `*` の条件として扱い、意図しない曜日や日に発火しない。

スケジュールの分への丸めは、その時点の秒・ミリ秒分を実時刻から引く。cron の再開位置も保存済み進捗が属する分の次の境界にそろえ、秒・ミリ秒を含む進捗から次の分を飛ばしたり、ずれた秒数で catch-up したりしない。夏時間終了時の重複したローカル時刻を setter で再解釈して、前の時刻へ巻き戻さない。この巻き戻りによる catch-up のずれや単発予定の遅延を防ぎ、秒を含む過去のタイムゾーン offset でもローカルの分境界を維持する。

同じ listener の tick が実行中なら、重なる tick と callback からの再入は実行しない。停止後は実行中だった一件より後の catch-up と別エントリを送らない。`all` の catch-up は直近1440分以内の対象を古い順に配送する。古い検索窓に固定されて週次・月次の現在の発火を見落とすことを防ぐ。
