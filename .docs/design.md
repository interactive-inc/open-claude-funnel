# 接続ライブラリとしての境界

Funnel のジョブは外部の接続を共有し、Agent SDK・Claude Code Channels などの購読者へイベントを届け、返信を外部へ返すこと。エージェントを起動するアプリケーションはホストが作る。SDK・MCP を包まず、ホストが使う入力列と通知値を提供する。[組み込み契約](embedding.md)を参照する。

## 所有者

| 対象 | 所有者 |
| --- | --- |
| Socket Mode / Gateway / poll、再接続 | Flume |
| 接続定義、配信先、fanout / exclusive、offset と再送 | Funnel |
| Agent SDK の query / session、MCP Server / transport / tools | ホスト。`/claude` の入力・通知をそのまま組み込む |
| 実行ディレクトリ、プロセス、設定の保存、資格情報 | ホスト |
| HTTP の待受・認証・公開範囲 | ホスト。Bun 用の薄い server helper は選択可能 |
| 再起動をまたぐイベント・発火状態の保存 | ホストが注入した store |

`new Funnel()` はメモリ内の設定を作る。ファイルを読まず、フォルダを作らず、ポートを開かない。コネクタと待受ポートと認証は明示する。SQLite は任意の sub-entry に隔離する。

Funnel の生成時に options の値を取得し、registry・チャネル操作・後から作る gateway に同じ時計・logger・停止 signal 等の参照を渡す。元の options オブジェクトを後から差し替えても、生成済み Funnel の依存先を変更しない。注入した時計を進めるなど、依存オブジェクト自身の操作は引き続き反映する。

## 構造

`lib/funnel.ts` が設定ストアとコネクタ registry を組み立てる。engine は接続・チャネルの規則を、gateway は購読・配信・HTTP/WebSocket 境界を持つ。CLI・Claude 起動・設定ファイル同期・ファイル IO の既定実装は持たない。

具体コネクタは `connectors/<type>` から必要なものだけ渡す。カスタムの Flume sources を合流する場合は `/channel` の manifest を使い、source 固有の状態保存は source に渡す。

## 不変条件

- スケジュールの予定 ID は同じ connector 内で一意にし、作成・復元・直接 listener 構築で重複を拒否する。checkpoint の共有で別の予定を実行済みにしない。`entries` の省略は空配列になるが、不正な型を空配列へ置き換えて保存しない。
- スケジュールの診断ログは配送の成否を変えない。診断・onFired のエラー報告の同期例外や Promise 拒否を捕捉し、後続予定・成功済み checkpoint・元の通知エラーを失わない。診断保存の失敗は logger へ通知し、その logger の失敗も処理へ戻さない。通知と発火状態の保存は引き続き必須の成功境界とする。
- スケジュールの start は同時に一つだけ有効にする。停止・再起動後に古い実行から後続予定や timer を再開しない。通知・onFired の待機中に再起動した場合は、その処理の確定後に新しい実行の初回 tick を進める。再起動の start は待機登録までで戻り、通知内から呼んでも待ち合わせで停止しない。成功済み通知の checkpoint は停止後も保存する。host signal と起動用 signal のどちらの取消でも実行を止める。
- スケジュールの時計は発火判定・状態読み取り・次の timer の計算前に検証する。Invalid Date で未来の予定を発火したり、不正な checkpoint を保存したりしない。timer を計算できない場合は接続を非稼働にし、エラーを通知する。時計を直した後の明示的な再起動は可能とする。
- 発火 checkpoint は host store の読み書きで Map と Date を切り離し、不正な時刻を `schedule checkpoint must be a valid timestamp` で拒否する。検証前に状態を削除したり通知したりしない。保存に失敗した場合はホストが保持する以前の Map を変更せず、未保存の発火は再試行対象に残す。
- 配信前に offset と再送先を記録する。保存失敗を隠してライブ配送を続けない。
- 同期的な保存・配送処理から公開へ再入させない。再入は次の offset の採番前に拒否し、保存順・ライブ入力・再送順を逆転させない。時計と配信データの準備は保存前に済ませる。`onEvent` は配送完了後に呼び、そこからの派生入力の公開は可能とする。
- 配信値は発行元・購読者の可変オブジェクトから切り離し、別の購読や再送履歴を書き換えられない snapshot にする。
- fanout と exclusive の配送先、明示停止、停止途中のキャンセルを保持する。
- 再起動が接続終了を待っている間も、後から来た停止・全体停止・再起動の要求を優先する。古い再起動要求は接続を開き直さず、取消結果を返す。全体停止が完了した後の新たな明示的再起動は可能とする。
- 接続の実行状態・起動ロック・再試行・停止意図は `(channelId, connectorId)` の組で識別する。名前は変更可能なラベルであり、区切り文字を連結したキーにはしない。
- 配送時はその ID の現在の設定を参照する。削除した接続の入力を同名の新しい接続として届けない。監視処理は削除した接続を閉じ、失敗・停止の状態も対応する ID がなくなった時点で解放する。
- 環境変数参照からの資格情報は、渡された環境辞書自身が持つ空でない文字列だけを使う。継承プロパティや文字列以外の値を token に変換せず、未設定として外部接続前に拒否する。
- コネクタの更新は、指定された設定値を検証してから保存する。Slack の `minify`、GitHub の取得間隔、資格情報スロットの不正な型を成功扱いで無視しない。省略された設定は引き継ぎ、検証に失敗した更新は保存済み設定を置き換えない。
- コネクタ操作は descriptor の operations 自身に登録した関数だけを呼ぶ。未登録名や prototype 由来の名前は通常の未定義操作エラーにし、設定を変更しない。標準オブジェクトと同名でも明示した操作は利用できる。
- 同一プロセスの入力列も WebSocket と同じ配送先選択・再送を使う。全件を観測する onEvent を配送先として代用しない。
- SDK / MCP のインスタンスと設定を複製・所有しない。入力列を止めてもホストの SDK タスク・MCP サーバーには干渉しない。
- `alive` は接続または復旧処理が生きていること、`connected` は実接続を表す。根拠は Flume の現在値で、遅れて届く状態ログは履歴として扱う。
- 自動復旧は listener registry が失敗・欠落した接続だけに適用する。Flume が接続し直している間は介入しない。
- 既定のメモリ再送は件数とバイト数で制限し、保持の削除で offset を巻き戻さない。
- メモリログも offset の昇順で再送・保持削除し、保存順序の逆転で新しい履歴を落とさない。保持中の同じ offset の重複や不正な offset は保存前に拒否する。メタデータの取得に失敗した保存では本文・バイト数・最大 offset を変更しない。
- offset は非負の安全な整数で復元し、発行する offset はその範囲内で単調増加させる。壊れた保存先の最大値を受け入れて初期値へ戻したり、小数・Infinity の位置を配信したりしない。上限に達した後の公開は、保存・配送・採番の変更前に拒否する。
- gateway の時計は有効な日時を表すミリ秒値として検証し、不正な時刻で起動・公開を進めない。稼働時間と最終配送時刻は時刻 0 を未設定と区別する。メモリ時計は構築・設定・取得時に Date をコピーし、ホストの日時の加工で時計を変更させない。
- SQLite も採番の最大値を本文とは別に保存する。本文と採番を同じ transaction で更新し、保持削除・clear・再起動で seq / offset を再利用しない。既存 DB の移行では残っている行の最大値を引き継ぐ。移行前に削除済みだった採番は復元できない。
- SQLite の件数・期限・バイト上限による行削除は、本文と採番と同じ transaction に含める。保持削除が失敗した入力は保存も配送もしない。commit 後の VACUUM と古い exclusive 割当の掃除は保守処理として分け、失敗時も成功済みの保存結果を失敗へ変えない。
- 同一プロセスの再送はページ単位で読み取りに追従し、履歴件数をライブ入力のキュー上限と混同しない。購読開始時の再送上限と、それ以降のライブ入力を分けて重複を防ぐ。
- 注入した永続ログはホストが閉じる。ホスト所有のサーバーはホストが停止する。Bun helper が所有するサーバーの停止では古い接続も閉じる。
- gateway の停止開始後は HTTP 操作・WebSocket 購読・既存 registry 経由の再起動を受け付けない。本文の読み取り後にも停止を確認し、停止をまたいだ要求から新たな外部送信を始めない。gateway が所有する購読と registry を終了し、ホスト所有の待受と独自のルートは継続できる。
- 同じ gateway の並行した `start()` は一つの起動を待ち、同じ成功・失敗を返す。途中の呼び出しで稼働開始時刻を更新しない。起動中の全体停止は起動を失敗させる。致命的な起動失敗では開いた接続と所有する待受を閉じ、明示的な再試行では新しい起動時刻を使う。
- observer から停止を待っても循環待ちしない。callback の配送と source の停止を混同しない。
- 配信 observer の例外、Promise / thenable の失敗は logger と `onError` へ独立して渡す。エラー通知先の同期例外や非同期失敗で、他の配送やプロセスを止めない。配送中に登録した observer は次回から参加し、解除・再登録で同じイベントを二度呼ばない。
- gateway の起動・購読・切断の通常ログも、接続状態を変更する処理と分ける。logger の失敗は `onError` へ渡し、待受だけが残った起動失敗や WebSocket callback の例外にしない。再送失敗の logger と `onError` は独立して呼び、通知先の失敗をホストの WebSocket callback へ漏らさない。
- listener registry もログと `onError` の同期例外・非同期失敗を接続管理へ戻さない。通常ログの失敗で接続を停止したり、停止結果・再試行可否・自動復旧を変更したりしない。起動の期限後に完了した接続の後始末でも、元の失敗を通知して未処理の Promise 拒否を残さない。
- 起動の期限と復旧待ちにキャンセルを伝え、正常起動や停止後に不要なタイマーを残さない。ホストが独自の sleep を渡す場合も、渡された AbortSignal に従う。
- 組み込みの Slack / Discord / GitHub listener はホストの停止信号と registry の接続所有信号を合成して Flume へ渡す。Slack の事前認証 HTTP と応答本文の読み取りにも同じ信号を伝え、取り消された起動から遅れて接続を開かない。
- Slack は listener 自身の実行スコープも取り消せるようにし、直接の停止を認証・前処理・reaction へ伝える。停止後に新しい配送や補助送信を始めず、旧スコープの遅延完了で再起動済みの接続を変更しない。実行中の同じ listener への重複起動は拒否し、取り消された Flume の起動が遅れて成功しても接続を閉じる。

0.72 は起動管理と暗黙のディレクトリを削除する破壊的変更。旧 API の互換 facade を重ねると同じ責任が本体へ戻るため設けない。

## 受信処理が遅い場合

Slack の受信重複はチャネルとイベント時刻の組で識別し、10秒の窓で除外する。窓を過ぎた判定を別イベントの到着有無に依存させない。空の識別情報を同じイベントとみなさず、JSON 化に失敗した処理では重複履歴を確定しない。これは受信の短期重複除外であり、外部副作用の実行完了や一度だけの処理を保証するものではない。

Flume source の入力は Flume の上限付き pull stream で直列に処理する。既定のバッファはログを含めて 1000 件で、超過時は Flume の drop-oldest と overflow ログに従う。無制限の Promise 待機列は作らない。この段階で未処理の入力は Funnel の再送ログへ記録されていないため、再送の保証範囲には含まれない。

停止は待機中の入力を破棄する。実行中のホスト callback の完了は待たず、callback 自身からも停止できる。状態ログの処理は完了させてから stopped を記録する。配送失敗と source の終了失敗は診断ログとホストの logger へ渡す。

受信 callback が失敗した場合も、後続イベントの配送を継続する。受信・起動・切断のエラーを受ける診断ストアや logger の例外は独立して扱い、片方の障害で他方への通知を省略したり、配送ループを終了したりしない。起動の失敗は元のエラーを呼び出し元へ返し、切断のエラー報告で停止処理を中断しない。logger が返す Promise の拒否も未処理の拒否にしない。

Slack の reaction は配送後の補助処理として進め、その失敗通知も診断ストアと logger へ独立して渡す。通知先の同期例外や Promise の拒否で未処理の拒否を作らず、後続の受信を妨げない。Flume のログ変換と診断 recorder は通知先の戻り値を捨てず、呼び出し元が非同期失敗を観測できるようにする。

## 定期実行の再試行と停止

schedule connector は一件の配送が成功するたびに、ホストの発火状態ストアへ進捗を保存してから `onFired` を呼ぶ。後続の配送が失敗しても、保存済みの成功分を再実行しない。配送とストア保存は別の操作なので、配送後に保存が失敗した場合やその間にプロセスが終了した場合の重複は、利用側で `schedule_id` と `fired_at` を用いて防ぐ。

既定の発火状態は channel ID と connector ID の組で分離し、ID 内の区切り文字で衝突させない。同じ ID の接続を再作成した場合は状態を引き継ぐ。メモリ状態ストアは保存・読込時に日時もコピーし、`onFired` に渡す予定と日時も内部状態から切り離す。実行用の予定は listener 構築時にコピーする。ホストが渡した設定や callback の引数を加工しても、後続の発火の ID・本文や保存済みの進捗に影響させない。設定変更はホストの設定更新と listener の再作成で反映する。

cron は5フィールドの十進整数・範囲・リスト・step を扱う。空の範囲端点・値のない step・16進数・指数表記は受け付けない。日と曜日のいずれかが `*` から始まる場合は両方の一致が必要で、両方が数値から始まる場合はどちらかの一致で発火する。`*/2` も先頭が `*` の条件として扱い、意図しない曜日や日に発火しない。

スケジュールの分への丸めは、その時点の秒・ミリ秒分を実時刻から引く。夏時間終了時の重複したローカル時刻を setter で再解釈して、前の時刻へ巻き戻さない。この巻き戻りによる catch-up のずれや単発予定の遅延を防ぎ、秒を含む過去のタイムゾーン offset でもローカルの分境界を維持する。

同じ listener の tick が実行中なら、重なる tick と callback からの再入は実行しない。停止後は実行中だった一件より後の catch-up と別エントリを送らない。`all` の catch-up は直近1440分以内の対象を古い順に配送する。古い検索窓に固定されて週次・月次の現在の発火を見落とすことを防ぐ。
